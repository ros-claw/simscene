# SimScene 快速开始

从 GitHub 获取源码的用户请先阅读[开源发布说明](开源发布说明.md)。下文的
`/home/dell/`、`/data/omniverse/` 与默认示例状态描述原实施工作站；其他机器
需要自行安装运行时、获取所选资产并配置相应路径。

SimScene 目前是开发版。它支持在线发现资产、选择后获取、编辑场景、
启动 Isaac Sim 和读取实际图像及状态。三臂物理验收、负对照和一次独立
智能体三臂组合已通过；路线交换及独立的重试修复用例也已验证。实际测试范围、失败记录和未验证事项见
[validation.md](validation.md)。

在当前工作站，SimScene 已注册到 Codex MCP，项目 skill 已安装，Isaac
路径已配置为 `/data/omniverse/isaac-sim-6.2.0/python.sh`。在本项目的
Codex 会话中可以直接描述要生成的场景；命令行可使用
`/home/dell/.local/share/simscene/venv-v30/bin/simscene`。这是本地 MCP
注册，不代表已安装到桌面插件市场。

当前工作站也保存了一个可继续编辑的三臂场景，ID 为
`three_arm_online_example`。它使用的三个在线资产及依赖已放入容量受限的
本机缓存，控制器文件已重新生成并与已验证运行的文件核对。可在 Codex 中
要求修改该场景，或用以下命令启动新的完整运行：

```bash
/home/dell/.local/share/simscene/venv-v30/bin/simscene run \
  --scene three_arm_online_example --steps 36000 --seed 17 \
  --case /home/dell/.local/share/simscene/examples/three_arm_online_example/case.json \
  --archive-verified-objects
```

源场景的 18 件实机运行已通过；这个重定位后的副本也已完成 120 步加载、
物理运行和相机烟测，但尚未单独重跑完整的 18 件分拣。重新运行会使用
仿真机器的 GPU 与存储空间。

在另一台仿真机器上安装本项目和与该 Python 环境兼容的 USD `pxr` 绑定，再配置
Isaac Sim 的 `python.sh`：

```bash
python3 -m pip install -e '.[ik]'
simscene configure --isaac-python /绝对路径/isaac-sim/python.sh
simscene doctor
simscene search 'industrial conveyor'
```

默认使用 NVIDIA 公共 USD Search 服务，搜索阶段不下载整个资产库。
选定资产后，用 `simscene inspect 资产地址` 查看元数据与依赖，再用
`simscene acquire 资产地址` 获取该资产。MCP 调用对应 `asset_search`、
`asset_inspect`、`asset_acquire` 和 `job_status`；获取结果中的 `root` 是
仿真端的本地 USD 路径。请检查依赖状态和各资产的许可证。可通过
`USD_SEARCH_API_URL` 或 `simscene configure --usd-search-url 地址` 更换服务。

使用 `python3 plugins/build.py --output /绝对路径/新目录` 构建适配包；
输出分别包含通用、Claude Code 和 DeepSeek Harness 目录。构建不会自动修改
客户端配置或安装插件。客户端接入、Python 版本和依赖要求见
[packaging.md](packaging.md)。主 skill 引导智能体检查资产、搭建场景、运行、
观察并依据结果修改；机器人轨迹和碰撞安全仍须由实际运行和检查器确认。

如果另一台仿真机器也保留了本仓库的验收证据，可在配置 Isaac 和 USD Python
依赖后运行 `python3 experiments/install_local_verified_example.py` 来建立同名
示例。脚本只获取示例选中的三个资产、核对原运行的内容锁并生成控制器；
若同名场景已存在或在线内容发生变化，它会停止，不覆盖原场景。

需要调整已有场景时，智能体可用 `scene_plan_retime` 提出投料时间修改，
用 `scene_plan_swap_routes` 提出两条单类别分拣路线互换，或用
`scene_plan_translate_group` 提出一组物体和指定机器人路点的平移。这些
工具返回可检查的操作和场景版本；应用修改后仍需重新运行并检查。
如果多台机械臂需要同时工作，`scene_plan_synchronize` 可依据一次完整、
校验通过的实际运行，提出投料顺序和间隔；修改后必须重新运行，并检查
`run_verify` 的 `parallel_steps`、物理结果和碰撞记录。
匹配的 Franka 配置可在场景层显式设置实验性夹爪力和摩擦，不改写原始
资产，参数需要针对实际模型与物料验证。
可通过机械臂跟随配置中的 `avoid_obstacles` 指定需要反应式避让的静态碰撞
盒或球，并设置 `obstacle_margin_m`。该功能是实验性的，必须检查实际运行
与碰撞记录，不能将规划结果当作完整轨迹安全证明。照明支持环境穹顶灯、
方向光、球形灯和矩形灯，可根据实际镜头调整并重新观察。
对于支持的标准取放循环，`scene_plan_stream_case` 可依据场景和明确给出的
料箱内边界生成物理检查用例；将结果作为 `simulation_start` 的 `case`
参数即可冻结用例并启用核验归档。此类用例用于观察和计数，不等同于独立
预先冻结的正式验收用例。
对于支持的三种实验性机械臂，可用 `scene_plan_collision_audit` 提议逐物理
步的碰撞检查配置。检查资产及允许的机械连接例外，应用返回的操作后重新
生成用例，再将返回的 `collision_policy` 加入用例，运行并检查验证报告。
该检查使用凸包近似，不覆盖被排除的机械对，也不能证明连续扫掠轨迹安全。

若希望自己的客户端电脑不保存 3D 资产，可在远程 GPU 机器上运行服务：

```bash
# 远程仿真机器
simscene mcp --transport streamable-http --port 8765

# 客户端电脑，另开终端建立 SSH 隧道
ssh -L 8765:127.0.0.1:8765 用户@仿真机器
```

服务只绑定远程机器的 `127.0.0.1`；客户端通过 SSH 隧道连接本机
`http://127.0.0.1:8765/mcp`。资产、缓存和仿真运行记录位于仿真机器，
客户端可获取预览图、状态和视频分块。已经实测本机 SSH 隧道；跨机器
环境仍需按实际网络和客户端测试。资源缓存默认有容量限制，运行记录和
生成的机器人配置另有存储空间需求。
