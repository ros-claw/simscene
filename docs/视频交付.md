# 原生录制与通用视频交付

本轮输入与目标见仓库根目录的 20261030 视觉升级实施单。下面描述实际接口；画质和物理验收以对应运行记录为准。

两个技能按能力划分：`build-scene` 负责在线选材、空间关系和运行观察；`deliver-scene-video` 负责拍摄、短片反馈、真实录制、剪辑和视觉检查。三臂配方保存在 `examples/precision_sorting_corner/recipe.json`，通用工具不识别场景或机器人名称。

## 录制规格

通过 `scene_apply` 应用：

```json
{"op":"set_presentation","presentation":{"profile":"technical_showcase_1080p","capture":{"anti_aliasing":"dlss_quality","exposure_ev":0,"depth_of_field":false,"motion_blur":false},"output":{"codec":"h264","crf":18,"preset":"medium","pixel_format":"yuv420p"},"budget":{"max_cameras":2,"max_recording_bytes":8589934592,"min_free_bytes":2147483648},"diagnostics":{"keyframe_interval_s":10,"png_seconds":0}}}
```

`preview` 为 640×360/2fps；正式默认 1920×1080/30fps；4K 是可选规格，需要另外确认预算。全局 profile 为每个相机设置录制率，已有的 `record_fps` 可以覆盖它。正式录制前应删除不用的相机，核对总机位数。原场景没有 profile 时保留旧行为。

相机可单独配置：

```json
{"kind":"camera","position":[2,-3,2],"record_fps":30,"preview_fps":1,"camera":{"resolution":[1920,1080],"focal_length_mm":35,"horizontal_aperture_mm":36,"focus_distance_m":3,"f_stop":0,"clipping_range_m":[0.01,1000],"capture_window":{"start_step":2820,"end_step":3420}}}
```

插件统一宽、高顺序；实际 RTX 传感器接收高、宽。镜头长度由毫米转换为 USD 的十分之一 stage 单位；米制场景中换算为毫米除以100。焦点和裁剪范围使用米。视场由焦距、传感器画幅和分辨率共同决定。关闭景深时 USD f-stop 为0。

30fps 在60Hz物理下每两步采集一次。上例记录2822至3420步，共300帧、10秒。视频第0帧对应仿真47.0333秒，不是仿真0秒。可以慢速离线计算，不能依据墙钟跳过采集。实际尺寸、物理步、模拟时间、视频时间写入逐帧 JSONL；新录制另外记录 Kit update、绝对物理步和 stage timecode。传感器 RGB 接口本身不提供独立曝光时间戳，不能把这些应用时刻描述为硬件同步认证。

`camera_path` 可以保存一串 `time_s/position/target` 节点，导出为 USD 位姿采样。主任务机位应稳定；相机移动段可以从剪辑中排除。路径和 orbit 互斥。

## 渲染、颜色与存储

显式配置在打开 stage 后应用，并在传感器启动后重新应用和读回，因为 Isaac 可能在初始化时覆盖曝光设置。DLSS Quality 与 DLAA 可对照；当前 worker 不静默吞掉缺失选项或已生效值与请求值的差异。读回保存到 `render-settings.json`，并纳入输出完整性锁。读回确认配置值，不代替观察画面。

录制器验证原帧实际形状和 uint8 类型。配置了交付渲染时，RTX 采用显示 sRGB 输出；FFmpeg 将 RGB 全范围转换为 BT.709 SDR 的传递函数、矩阵和有限范围 YUV420P，再编码 H.264。不是只修改色彩标签。原帧和解码帧的像素对比要计入这一转换及有损压缩。

20261031连锁挑战的实测发现，旧 `colorspace` 链处理packed RGB时会被FFmpeg隐式插入一次YUV转换，之后GBR标记与实际数据不符，造成灰阶和青蓝偏移。dev2改用明确的planar GBR→`zscale`→BT.709 YUV链；检查器和合成关键帧从BT.709逆变换回显示sRGB。FFmpeg需要启用`zscale`。纯色帧经过实际H.264编码、检查器解码后逐通道核对，并加入回归测试。旧源片及其配置保持原样，不用修复后结果回写旧结论。

录制配额和资产缓存配额分别设置；不足时显式失败，不自动漏帧。默认保存首张原生 PNG 和每10秒关键帧。`png_seconds` 可保存开始录制后的前0–10秒全部原帧，适合诊断，不要求完整任务全程 PNG。

## 规划、编辑和检查

`scene_plan_presentation(scene_id, subject_ids, regions, ...)` 从实际 bounds 生成全景与细节机位和普通 scene operations。region 包含 `id/min/max` 和可选 action/subject_ids。规划器的保守构图仍需检查遮挡、主体大小和高光；它不会自动证明画面好看。

`run_presentation_events(job_id)` 将冻结 spec 的 phase 类型与真实 transition/spawn 时刻关联，返回主体和对象ID。事件本身不代表物理成功。Agent 应结合关键动作与检查结果选择区间，不能在编辑器中写死机器人名字或阶段序号。

`video_export` 输入：

```json
{"segments":[{"run_directory":"/simulation-host/state/runs/<run-id>","camera":"detail","start_sim_time_s":47.0333333333,"end_sim_time_s":57.0333333333,"speed":1,"title":"Contact and lift"}],"destination":"/simulation-host/delivery/demo.mp4","output_resolution":[1920,1080]}
```

源录像必须通过输入/输出锁和逐帧时钟检查。导出保留源采集率；低帧率素材不能通过重复帧成为真实30fps。默认拒绝放大，显式允许时记录倍率。比例通过等比缩放与留边处理。每段保存合成关键帧；`.edit.json` 保存源文件、锁、帧范围、仿真时间、播放时间、速度和编码配置。不同 run 或调速应在交付记录中明确。

`video_inspect(path, output_dir, ..., job_id, camera)` 为源片核对实际规格、解码帧数、物理时间清单及原生关键帧尺寸；为带 `.edit.json` 的成片核对源哈希和剪辑时间关系，生成代表帧。查看这些图像，并检查包含关键动作与切镜的运动片段之后再交付。检查器有意不把单一锐度、过曝率或图像重复率当作视觉合格证明。

新录制的 manifest、原生 PNG 和渲染读回均纳入 `evidence-lock.json`。锁只能检查保存后的改变，不能证明物理任务成功。物理验证仍使用原有 `run_verify` 和冻结 case。

## 在线道具与可编辑布局

新增 `scene_measure` 和 imported asset 的 `place_on/arrange_line/arrange_grid/align` 支持最终世界 bounds 与底部锚点。支撑面用规范化本地米制 `support_surfaces` 声明有效区域与孔洞排除；外部 bbox 顶端不视作工作台面。摆放可以检查 `avoid_ids/keepout_bounds/clearance_m`，保留运行活动区。几何容纳与动态稳定是不同检查。

导入道具保留原始材质；必要时 `material_overrides` 只针对 Asset 下的相对 prim。`asset_physics: visual_only` 显式移除场景引用中的物理，源文件不改动。控制器资产不允许使用此选项。若源单位缺失或有明确证据表明错误，`asset_metrics` 要写明单位/轴和检查理由，不能悄悄猜比例。

在线来源和内容锁见示例 `assets.lock.json`，可以用 `experiments/acquire_recipe_assets.py` 按需获取并核对文件指纹。该脚本只拉取已经选中的固定来源；重新发现资产仍应使用在线搜索。模型、贴图和第三方许可证不随 Git 仓库重新分发。

Hugging Face获取支持固定提交中被USD引用的`<UDIM>`纹理：只枚举所选纹理目录的同名前后缀瓦片，完整翻页后按容量获取并保存内容锁，不枚举整个资产库。每模式最多32页、256瓦片；来源/提交变化、缺瓦片或超预算不视为完整资产。即使USD因第一张瓦片存在而不再报告缺失，下载失败的其他瓦片仍使包保持missing。对旧missing包再次显式获取会创建新的内容指纹，原包不改写。

渲染与编码参数参考 [NVIDIA 性能手册](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/reference_material/sim_performance_optimization_handbook.html)、[Omniverse 相机单位](https://docs.omniverse.nvidia.com/materials-and-rendering/latest/cameras.html)、[FFmpeg colorspace](https://ffmpeg.org/ffmpeg-filters.html#colorspace)；实际 RC 安装的生效值必须从本次运行读回。
