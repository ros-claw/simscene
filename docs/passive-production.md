## 第一个动作与负对照

在有兼容 Isaac Sim 的 GPU 主机安装开发版和 USD Python 绑定。以下小实验不下载在线模型，也不修改默认 MCP 注册：

```sh
python3 -m pip install -e . usd-core
python3 experiments/run_module_bench.py --kind line \
  --output ./state/my-first-domino-bench \
  --isaac-python /absolute/path/to/isaac-sim/python.sh
```

命令先封存条件和两份初始场景，再分别运行八秒。正例由第一张牌的初始倾斜在重力下启动；负例仅移除第十张牌，检查上游九张仍倒下、后十张保持安静。牌中心间距为 9 厘米，移除后的 18 厘米断口超过 14 厘米牌高，避免直接跨过缺口。它不是全屋作品的唯一放球实验。`bench-result.json` 包含观测指标、每个 job/run ID 和有限配置的工程结论；原生低成本视频、USD、输入及输出锁均留在对应 `state/runs/`。

将 `--kind line` 换成 `--kind bridge`、使用另一个新输出目录，可测试未上闩柜门自行落下、球经过门板到达接收台，以及锁住铰链后的对照。这个模块不自动发明锁闩或按时间释放物体。测试是开发者的小型工程检查，不等同于独立全屋验收；改变尺寸、载荷、接缝或方向要重新做局部试验。

输出目录必须是新目录，避免覆盖失败记录。长任务由宿主等待同一个 job，模型只需要读取最终短结果；等待超时保留原 job，不自动重启。

## 用参数代替数百条手写操作

```sh
simscene mechanism compile --help
python3 skills/build-scene/scripts/plan_mechanism.py /path/definition.json --output /path/plan.json
```

定义示例：

```json
{"kind":"domino_arc","prefix":"wave","parameters":{"count":23,"origin":[2,-1,0.7],"orientation_wxyz":[0.7071067811865476,0,0,0.7071067811865475],"radius_m":0.65,"sweep_degrees":100,"support_thickness_m":0}}
```

返回短引用、指纹和输入/输出位置；完整普通操作保留在计划文件，仍可编辑、导出 USD、逐件检查。弧线的 origin 位于第一张牌下方，初始切线为局部 +X；不是圆心。当前模块限水平支撑面，可旋转水平朝向。`support_thickness_m:0` 要求调用方提供承托。静态无重叠或 schema 通过不代表物理传播成功。

仓库根目录可直接执行脚本。便携包使用自身 `skills/.../scripts/`；安装器复制到项目的技能通过 `.simscene-plugin-root` 找到相应 vendor 代码。搬迁安装目录后应重新安装到新的项目路径。

## 先查第一处断点

```sh
simscene diagnose --report retained-report.json --case frozen-case.json --output diagnostic.json
```

该工具消费已有被动网络检查报告，寻找从已启动事件到缺失/拒绝事件的最早因果边，返回有限长度摘要、源文件指纹及局部试验建议。若报告只有事件阈值，就明确标为事件边界；不会伪造接触、倾角、10 毫米障碍物或根因。初始包围盒邻居只是候选障碍物。

断绳后抽屉不动，只有在配重已经下降时才能支持负对照结论。上游没有到达时，先修上游；未知、记录缺步或 case 不匹配都不能改记为成功。当前诊断不覆盖任意自定义实验 schema，复杂判定仍使用原始检查器。

## 本轮小试暴露的通用故障

| 观察 | 最小下一步检查 |
| --- | --- |
| 球没有沿画面里的斜板行进 | 静态支撑必须显式 `collision:true`；可见几何不是碰撞证据。核对导出 USD 的有效碰撞属性。 |
| 接收物被撞动，后来翻倒或掉出台面 | 同时检查速度、姿态、完整包围盒和承托余量；中心点一度进入目标范围不代表最终稳停。 |
| 任务看似完成，尚未写提交就用尽预算 | 将完整轨迹留在文件；用宿主等待同一 job，读有针对性的短摘要，并保留提交收据所需预算。 |
| 检查器拒收，但源 JSON 的省略字段在引擎中有默认值 | 先区分接口判定和真实物理；保留冻结判定，另立修正版，使用编译后的有效状态做接口回归，不改变物理阈值。 |

这些教训来自本轮实际失败，不是新增的通过条件。P2 两组最终都出现未稳停、翻倒或承托失败；修复评测接口后仍然未通过。

## 先保留记录，再改变机位

新 `simscene replay prepare/render/status` 接口可从逐步记录提取准确刚体位置，为已有运行补拍固定近景和跟拍。它关闭派生舞台的刚体与关节、保持时间线停止，并检查新增物理步数为零。原始 USD 不保存修改。镜头是“记录重渲染”，不是原始相机拍下的素材，也不增加一次物理成功。

60 Hz 位置逐帧以 30 fps 播放可得到明确标注的 0.5× 慢动作，不插帧；原速每隔两个物理步取一帧。缺失样本直接失败。使用方法和出处边界见 [causal-editing](../skills/deliver-scene-video/references/causal-editing.md)。原速剪辑用逐帧时钟定位，不用导演片的播放器时间代替仿真时间。中文导出选择实际含中文字形的字体，并核对成片；`video_export` 支持 `font_file`。

## 成本结论需要实测

四次小规模 A/B 试点使用同模型、预算、相同 v43 MCP、两个陌生目标和各自负对照。A 使用原技能，B 使用冻结的候选制作包；这测的是整个包，不是只修改文字的效果。逐请求输入、缓存、输出与推理字段、失败、重试和等待分别记录。缓存输入属于输入，推理输出属于输出，不能重复相加。缺失费用或 provider 请求 ID 标为未知。

物理质量、预算和提交完整性必须同时看。仅一组完成时报告同预算可完成性；只有两组完成相同验收才能比较节省比例。近 30 小时的历史开发不作为 A 组，也不从时间反推 token。实际使用边界见验证文档；本轮试点未提供有效节省率估计。
