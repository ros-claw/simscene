# Integration capability and evidence scope

The integration development line builds on `30852a39e9e0043ea4c798d31194a9480ce1088e`.
It is not the same build as the separate DyCraft authoring line: the two lines
have both used version `0.2.0.dev2`, so a version string alone is insufficient
to identify a package. Record the commit, wheel hash, installed module path,
worker, checker, and independent backend runtimes for each qualification.

| Capability | Existing evidence at the integration baseline | Scope and remaining work |
| --- | --- | --- |
| USDCraft metadata and layout | Metadata-only catalog query; one single-hinge cabinet and three imported props in a measured layout | Explicit horizontal support and keepouts; proposal alone is not a physical verdict. |
| ArtVIP | One pinned door, explicit mass and drive repairs, driven run and no-drive control | One object and one scheduled hinge; neither all ArtVIP assets nor passive triggering are qualified. |
| USDCraft two-joint cabinet | One pinned three-link/two-slider asset; separate missing-second-drive control | One native graph and bounded scheduled drives; no independent payload interaction has yet been qualified. |
| USDCraft SDK | One trusted guide template; two prepared lengths and a CCD ball comparison | Isolated optional runtime, explicit static collision proxies, and a recorded density assumption. |
| Installed package | Portable, Claude and DeepSeek layouts build; the installed portable MCP applied an actual layout | The baseline package lacks the fixed cabinet example and has not demonstrated the complete installed MCP-to-Isaac workflow. |
| MobilityGen | Standalone fixed-route Jetbot pair | Experimental and outside the general scene job/MCP workflow; native velocity consistency is not verified. |
| DyCraft authoring | Separate development branch and its own recorded outcomes | Its earlier client qualifications remain incomplete; this integration line does not inherit them. |

The recorded physical examples use Isaac Sim 6.2.0-rc.14 on the documented
Linux host. Prepared assets, callbacks and frame records must be checked for
each new run. Hashes support integrity comparisons; they are not signatures.
See [catalog capabilities](catalog-capabilities.md) for per-source conditions.
